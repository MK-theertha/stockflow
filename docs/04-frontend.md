# Frontend (React app)

All client code is in `client/src`. It is a single-page app built with **Vite**, using
**React Router** for pages, **MUI** for components, and **Redux Toolkit** for the shared
master-data lists.

## How the app boots

```
main.jsx
└── <BrowserRouter>                  URL ⇄ page
    └── <Providers>                  app/Providers.jsx
        ├── <ThemeProvider>          dark MUI theme (app/theme.js)
        ├── <SessionProvider>        who is logged in (lib/session.jsx)
        ├── <Provider store>         Redux store (store/index.js)
        └── <NotificationProvider>   app-wide snackbar
            └── <App/>               routes (app/App.jsx)
```

## Routing

`app/routes.jsx` lists every page:

```js
export const USER_ROUTES = [
  { index: true, Component: page(() => import('@/features/dashboard/DashboardPage')) },
  { path: 'receivables', Component: page(() => import('@/features/receivables/ReceivablesPage')) },
  ...
];
```

- `page()` is `React.lazy`: each page is downloaded only when first opened, keeping the
  initial download small.
- `App.jsx` mounts `USER_ROUTES` under `/dashboard/user` and `ADMIN_ROUTES` under
  `/dashboard/admin`, both wrapped in `DashboardLayout`:

```jsx
<RequireRole role={role}>          // logged in with this role? else → /login or /
  <SubscriptionGate>               // active subscription? else → /pricing
    <DashboardShell role={role}>   // sidebar + top bar
      <Outlet />                   // the page for the current URL
```

- The sidebar is built from `app/navigation.js`. To add a menu item, add a route in
  `routes.jsx` and an entry in `navigation.js`.

These guards are for user experience only. **The API enforces the same rules**, so hiding a
page is never what keeps data safe.

## Talking to the API

### `apiFetch()` – one way to call the server

```js
import { apiFetch } from '@/lib/api-client';

const product = await apiFetch('/api/user/products', { method: 'POST', body: { productName } });
```

- Sends and parses JSON, includes the session cookie.
- **Throws an `Error` with the server's message** for any non-2xx response, so you can write
  `catch (error) { notify.error(error.message) }`.

### `useApi()` – load data for a page

```js
const { data, loading, error, reload } = useApi('/api/user/stock/low');
```

Use it for data only one page needs (reports, the dashboard, the stock ledger). Call
`reload()` after changing something.

### Redux – shared master data

Master data (products, categories, units, suppliers, customers, expenses) lives in Redux
because many pages need it (the invoice form needs products _and_ customers; the purchase
form needs products _and_ suppliers). Transactions such as invoices and purchases are loaded
per page with `useApi`. Each slice is generated by `store/createCrudSlice.js`:

```js
const { reducer, thunks } = createCrudSlice({ name: 'units', endpoint: '/api/user/unit' });
// thunks.fetchAll(), thunks.add(item), thunks.update(item), thunks.remove(id)
```

Rule of thumb: **list used on several pages → Redux; data for one page → `useApi`.**

## The session

`lib/session.jsx` exposes `useSession()`:

```js
const { data, status, signIn, signOut, refresh } = useSession();
data?.user; // { _id, name, email, role, image } or undefined
status; // 'loading' | 'authenticated' | 'unauthenticated'
```

The token itself is in an httpOnly cookie that JavaScript cannot read. On startup the
provider asks `GET /api/auth/session` who is logged in.

## Shared building blocks (`components/common`)

| Component          | Use it for                                                         |
| ------------------ | ------------------------------------------------------------------ |
| `PageHeader`       | Title, subtitle and buttons at the top of every page               |
| `DataTable`        | Any list: search box, pagination, loading and empty states         |
| `CrudPage`         | A complete list/add/edit/delete page from a column + field config  |
| `EntityFormDialog` | A form dialog generated from a field list                          |
| `ConfirmDialog`    | "Are you sure?" before deleting                                    |
| `LineItemsEditor`  | Product / quantity / price lines for invoices and purchases        |
| `ImageField`       | Photo upload (Cloudinary) or URL, used as `type: 'image'` in forms |
| `StatCard`         | One KPI number                                                     |
| `useNotify()`      | `notify.success('Saved')`, `notify.error(message)`                 |

`CrudPage` shows how much a good abstraction saves. This is the entire Units page:

```jsx
const columns = [{ label: 'Name', render: (unit) => unit.name, search: (unit) => unit.name }];
const fields = [{ name: 'name', label: 'Unit name', required: true }];

export default function UnitsPage() {
  return (
    <CrudPage
      title="Units"
      noun="unit"
      stateKey="units"
      thunks={thunks}
      columns={columns}
      fields={fields}
    />
  );
}
```

## Public pages

The landing, login, register, pricing and checkout pages (`features/home`, `features/auth`,
`features/billing/PricingPage.jsx`) have their own marketing-style design and are not built
on the dashboard components. Everything inside the dashboard is.

## Styling

- The MUI **theme** (`app/theme.js`) sets dark mode, colors, font and component defaults.
- Prefer theme values in `sx`: `color: 'text.secondary'`, `bgcolor: 'background.paper'`,
  `borderColor: 'divider'`, spacing numbers (`p: 2` = 16px).
- Avoid hard-coded colors so the whole app can be re-themed from one file.
